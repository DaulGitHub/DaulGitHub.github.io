# personal_brand

Личный сайт-портфолио Мавлоназарова Даулета: статический сайт на [Hugo](https://gohugo.io/) с темой [hugo-coder](https://github.com/luizdepra/hugo-coder), автоматически собирается и публикуется на GitHub Pages.

## Структура проекта

```
content/           Markdown-страницы сайта (контент)
  _index.md        Главная страница (BIO)
  anti-bio.md      Страница "Анти-био"
  consulting.md    Страница "Консалтинг"
  twinspector.md   Страница "Twinspector"
layouts/           Переопределения шаблонов темы
  _partials/home/sections.html  Кастомный рендер контента на главной
static/images/     Статические файлы (картинки), попадают в корень сайта как есть
archetypes/        Шаблон для `hugo new` (заготовка новой страницы)
data/              Структурированные данные для шаблонов (сейчас пусто)
i18n/              Переводы строк темы (сейчас пусто — сайт только на русском)
themes/hugo-coder/ Тема оформления, подключена как git submodule
hugo.toml          Основной конфиг сайта (заголовок, меню, параметры темы)
.github/workflows/hugo.yaml  CI-пайплайн сборки и деплоя на GitHub Pages
public/            Собранный сайт (генерируется Hugo, в git не коммитится)
```

## Как устроен статический сайт

Hugo берёт файлы из `content/`, оборачивает их в HTML-шаблоны темы `hugo-coder` (с учётом переопределений из `layouts/`) и параметров из `hugo.toml`, и генерирует готовый статический сайт (HTML/CSS/JS) в папку `public/`. Никакого сервера и базы данных нет — на выходе просто статические файлы, которые можно отдавать с любого хостинга.

Ключевые моменты конфигурации (`hugo.toml`):
- `baseURL` — адрес, по которому сайт будет доступен.
- `theme = "hugo-coder"` — используемая тема.
- `locale`/`defaultContentLanguage = "ru"` — сайт одноязычный, на русском.
- `[[menu.main]]` — пункты меню в шапке сайта, каждый пункт ссылается на страницу в `content/`.
- `[params]` — настройки темы: имя автора, описание, ключевые слова, аватар, видимость копирайта и т.д.

## Как добавить контент

### Новая страница в меню

1. Создать Markdown-файл в `content/`, например `content/projects.md`:
   ```markdown
   ---
   title: "Заголовок страницы"
   ---

   Текст страницы в Markdown.
   ```
   Можно также сгенерировать заготовку командой:
   ```bash
   hugo new content/projects.md
   ```
2. Добавить пункт меню в `hugo.toml`:
   ```toml
   [[menu.main]]
     name = "Проекты"
     weight = 4
     url = "/projects/"
   ```
   `weight` задаёт порядок пунктов меню (меньше — левее/выше).

### Правка существующей страницы

Просто отредактировать соответствующий `.md`-файл в `content/` — заголовок в front matter (между `---`), текст ниже в Markdown.

### Картинки

Положить файл в `static/images/` и ссылаться на него в контенте как `/images/имя-файла.png` (или использовать как `avatarurl` в `[params]` конфига).

## Локальный запуск

```bash
hugo server -D
```

Сайт откроется на `http://localhost:1313/` с автообновлением при сохранении файлов.

Полная сборка (как в CI) — `hugo --gc --minify`, результат появится в `public/`.

## Как происходит деплой

Деплой полностью автоматический через GitHub Actions (`.github/workflows/hugo.yaml`):

1. При пуше в `main` (или `master`) запускается workflow `Deploy Hugo site to Pages`.
2. Job `build`: чекаутит репозиторий вместе с submodule темы (`submodules: recursive`), ставит Hugo указанной версии и собирает сайт командой `hugo --gc --minify --baseURL "<pages-url>/"`, результат (`./public`) загружается как Pages artifact.
3. Job `deploy`: публикует собранный артефакт на GitHub Pages.

Вручную задеплоить ничего не нужно — достаточно запушить изменения в `main`. При необходимости workflow можно запустить и вручную через `workflow_dispatch` (вкладка Actions в GitHub).
